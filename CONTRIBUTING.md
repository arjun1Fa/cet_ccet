## Contributing

Thanks for contributing to CET CCET.

### Development flow

1. Create a focused branch from `main`.
2. Keep changes scoped to one problem.
3. Run the relevant validation or test commands.
4. Update documentation when behaviour or configuration changes.
5. Open a pull request with a clear summary and validation notes.

### Pull request checklist

- [ ] The change has a clear purpose.
- [ ] Existing interfaces remain compatible, or the PR explains breaking changes.
- [ ] Tests or reproducible validation were added/updated where practical.
- [ ] Documentation/configuration was updated when needed.
- [ ] No credentials, private keys, model artifacts, or large generated files were added.

### Commit guidance

Use focused commit messages such as `fix:`, `feat:`, `docs:`, `test:`, or `refactor:`.
